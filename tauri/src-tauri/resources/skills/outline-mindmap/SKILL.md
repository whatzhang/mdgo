# 知识树 / 大纲 / 思维导图管理

## 核心思想（每次操作前必读）
- **先树后格式**：所有大纲/思维导图操作，先在**知识树（Knowledge Tree）模型**上构建与修改，再把树映射为持久化格式（默认 `.opml`）。**禁止直接以 XML 文本思维拼装文件**。
- 大纲（OPML 视图）与思维导图（jsMind 视图）是**同一棵树的两种可视化**，数据结构一致，用户可一键切换。
- 树模型定义见 `references/knowledge-tree-schema.md`；OPML 硬规约见 `references/opml-format.md`。

## 职责边界
- **创建知识树**：从用户描述 / 一句话主题 / 文档内容生成结构化树，落盘为 `.opml`。
- **从文档提取结构**：读 `.md`/`.opml`/`.mm`/文本 → 提炼为树（Document → Knowledge Tree）。
- **从对话生成结构**：用户长篇讨论/零散输入 → 归纳为主题树（Conversation → Knowledge Tree），**自动建议保存**。
- **编辑树结构**：增 / 删 / 移 / 合并 / 改节点（树级操作，再序列化写回）。
- **知识演进**：在既有树上增量扩展——新主题就近归并、同义合并、冲突消解（Knowledge Evolution）。
- **结构分析**：分析树的健康度（孤岛、失衡、缺关联），给用户建议（Tree Reasoning）。
- **视图切换**：`.opml` 文件由用户在前端打开即大纲视图，可一键切思维导图；导出 .mm 由前端完成。

## 工作流（标准五步）
1. **定位**：用户给路径直接用；未给时用 `ls`/`glob` 在知识库查找 `.opml`/`.mm`/`.md` 候选，向用户确认后操作。
2. **读取**：用 `read` 读取文件全文（.opml/.mm 是 XML 文本，.md 是 Markdown）。
3. **建树**：把内容解析为 Knowledge Tree（JSON 模型）——**先归一，再操作**。
4. **修改**：在树模型上完成增删移合并；再按目标格式序列化。
5. **写回与汇报**：新建用 `write` 写全文；修改用 `write`（结构大改）或 `edit`（单点小改）；向用户说明树的变化（新增/移动/合并了哪些节点）。

## 生成规则（AI 增强能力）
- **Document → Tree**：Markdown 标题层级直接映射树层级（`#`=根下第一级，`##`=第二级…）；正文段落择优并入最近节点 `note`；列表项（`-`/`- [ ]`）映射为子节点（勾选视作任务）。
- **Conversation → Tree**：长对话归纳为「主题 → 背景/问题/方案/决策/TODO」结构；要点不臆造，用户未明确的信息标注待确认。
- **Knowledge Evolution**：新增内容先查树上是否已有同义节点——有则归并（子节点并入），无则按就近层级挂载；避免同层出现语义重复节点。
- **Tree Reasoning**：分析时关注——①孤岛节点（无兄弟无子，孤立主题）；②失衡（某分支过深/过宽）；③跨域未关联（如"AI"与"Cloud Native"无连接）；给出可执行的结构建议。
- **Auto Outline**：一句话主题（如"我要学习 Kubernetes"）→ 生成标准学习/结构大纲（Architecture/Pod/Service/Network/Storage/Security…），用户确认后落盘。

## 存储与格式
- **默认写 `.opml`**（前端大纲/思维导图双视图兼容，规约见 `references/opml-format.md`）。
- **兼容读**：`.mm`（FreeMind，宽容解析，只取标题与嵌套）；`.md`（标题层级提树）。
- **转换原则**：Markdown → Knowledge Tree → OPML（**不是** Markdown 直接转 OPML——先在树模型上定结构，再落格式）。
- 新文件命名建议：`{主题}-outline.opml` 或沿用知识库既有命名习惯。

## 注意事项
- **XML 转义必做**（`& < > " '`），写完后自查一遍（见 opml-format.md §4-5）。
- 不伪造用户未提供的内容：新节点标题来自用户输入或文档原文；归纳性标题向用户说明来源。
- 新建文件前与用户确认路径；修改已有文件前确认目标（不要静默覆写）。
- 删除/移动节点前提示影响（删节点会连子树一起删）。
- 读取或写回失败时如实返回原因，不编造树内容、不重复无效调用。
- 若用户只要"看看结构/对话里画个图"，可用 mermaid mindmap 在对话内展示；**需要可编辑、可保存、可演进的知识树时，才落盘 .opml**。

## 输出规范
- 汇报时用缩进树形展示结构（如 `├── 一级 / │   ├── 二级`），让用户一眼看清层级。
- 完成落盘后告知文件路径与前端打开方式（大纲视图 ↔ 思维导图一键切换）。
