# 大纲笔记 / 思维导图（通用技能）

## 领域边界（每次触发先读）
本技能是**思维导图与大纲笔记**领域的通用技能，服务 `.opml`（大纲笔记）、`.mm`（思维导图）文件与一切树状知识：

- **处理**：
  1. **知识点总结输出**：把用户描述 / 文档 / 对话总结为树状知识点，保存为 `.opml` 或 `.mm` 文件；
  2. **文件总结解析**：读取 `.opml` / `.mm` 文件，解析并总结其内容（主题、结构、要点）；
  3. **通用树状知识**：树状结构的提取（md 标题层级、目录、嵌套列表等）、格式转换（树 ↔ .opml ↔ .mm）、树编辑（增删移合并）、结构分析。
- **不处理（其余一概不管，由对应技能负责）**：mermaid 图表代码（mermaid）、看板（kanban）、日程（schedule）、网页研究（web-research）、代码检索（code-lookup）、普通 Markdown 笔记写作（note-writing）、收藏整理（bookmark）等。
- 越界请求：明确说明「这不在 outline-mindmap 技能范围内」并指向对应技能，不执行、不硬套。

## 统一树模型（核心原则）
- **先树后格式**：所有大纲/思维导图操作先在**树模型**上完成，再映射为持久化格式；**禁止直接以 XML 文本思维拼装文件**。
- 大纲（OPML 视图）与思维导图（jsMind 视图）是**同一棵树的两种可视化**，数据结构一致，用户可一键切换。
- 参考文档：
  - 树模型与格式映射：`references/knowledge-tree-schema.md`
  - `.opml` 格式规约：`references/opml-format.md`
  - `.mm`（FreeMind）格式规约：`references/freemind-format.md`

## 三大能力

### 1. 知识点总结输出（创建 / 保存）
- 从用户描述 / 文档 / 对话提炼知识点，归纳为主题树（Document/Conversation → Tree）→ 保存为 `.opml`（默认大纲笔记）或 `.mm`（思维导图）。
- 规则：要点不臆造，归纳性标题向用户说明来源；新建前与用户确认主题、路径与格式；命名建议 `{主题}.opml` / `{主题}.mm`（优先中文）。

### 2. 文件总结解析（读取 / 总结）
- 读取 `.opml` / `.mm` → 解析为树模型 → 总结：根主题、层级结构、知识点清单、重点分支；在对话中汇报，或按用户要求转存为另一格式（如 .mm → .opml）。
- 解析失败 / 空文件：如实标注「无法解析」，不臆测、不补全。

### 3. 通用树状知识（提取 / 转换 / 编辑 / 分析）
- **提取**：md 标题层级（`#`→层）、目录结构、嵌套列表、JSON 树 → 统一树模型。
- **转换**：树模型 ↔ `.opml` ↔ `.mm`（读 `.mm` 宽容解析；写 `.opml` 严格按规约；写 `.mm` 用最小 FreeMind 骨架）。
- **编辑**：增 / 删 / 移 / 合并 / 改节点（树级操作，删除/移动前提示影响范围，序列化写回）。
- **分析**：树健康度（孤岛、失衡、缺关联）与结构改进建议。

## 通用工作流（五步）
1. **定位 / 确认来源**：新建时确认主题与保存路径；处理已有文件时用 `glob`/`ls` 定位 `.opml`/`.mm` 候选，向用户确认。
2. **读取**：`read` 读取源内容（`.opml`/`.mm` 为 XML 文本，md 按标题层级，对话为用户消息）。
3. **建树**：解析 / 归纳为树模型（**先归一，再操作**）。
4. **操作**：总结、转换或编辑，在树模型上完成。
5. **写回与汇报**：新建用 `write` 写全文；修改用 `write`（结构大改）或 `edit`（单点小改）；向用户说明树的变化与文件路径、前端打开方式（大纲 ↔ 思维导图一键切换）。

## 注意事项
- **XML 转义必做**（`& < > " '`），写 `.opml`/`.mm` 后自查一遍（见 opml-format.md §4-5、freemind-format.md §4）。
- 不伪造用户未提供的内容；删除/移动节点前提示影响（删节点会连子树一起删）；修改已有文件前确认目标，不静默覆写。
- 读取或写回失败时如实返回原因，不编造树内容、不重复无效调用。
- 汇报时用缩进树形展示结构（如 `├── 一级 / │   ├── 二级`），让用户一眼看清层级。
