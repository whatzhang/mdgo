# Knowledge Tree Schema（知识树模型 · 统一抽象）

> 本文件定义「知识树」——大纲与思维导图的统一抽象模型，也承载一切树状知识的归一化。
> **所有操作先在树模型上构建/修改，再映射为持久化格式（.opml / .mm）。禁止直接以 XML 文本思维拼装文件。**

## 1. 概念

知识树 = 有根有向树：

- 一个根节点（整棵树的主题）；
- 根下若干子节点，节点可无限嵌套；
- 每个节点只有唯一父节点；节点顺序有意义（同级按书写顺序展示）。

大纲（OPML 视图）与思维导图（jsMind 视图）是**同一棵树的两种可视化**，数据结构完全一致。

## 2. 节点模型（JSON）

```json
{
  "text": "节点标题",
  "note": "备注/说明（可选，支持 Markdown）",
  "color": "blue",
  "images": ["相对路径或链接"],
  "children": [ ...子节点递归... ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `text` | 是 | 节点标题（唯一结构语义字段，尽量短而准确） |
| `note` | 否 | 备注正文，可含 Markdown（如 `- 要点`、表格、代码块） |
| `color` | 否 | 仅视觉标记，**不承载结构语义** |
| `images` | 否 | 配图（相对路径或外链） |
| `children` | 否 | 有序子节点数组 |

## 3. 层级语义

- 树的深度 = 缩进层级 = 思维导图层级 = OPML 嵌套深度。
- 根主题 → 一级主题 → 二级主题 → …… 同级之间并列/分类，上下级包含/从属。
- 分类要正交：同一父节点下的子节点应是同一维度（如"技术栈"下不再混入"日程"）。

## 4. 多格式映射（持久化）

### 4.1 默认格式：OPML（.opml）

```xml
<opml version="2.0">
  <head><title>根主题</title></head>
  <body>
    <outline text="一级主题">
      <outline text="二级主题"/>
    </outline>
  </body>
</opml>
```

- 根主题标题在 `<head><title>`（**不是** body 里的 outline）；`<body>` 下直接放根主题的子节点。
- 映射：`text` → `text`；`note` → `note`；`color` → `COLOR`；`images` → `_images`；`children` → 嵌套 `<outline>`。
- 完整规约（转义、缩进、闭合）见 `opml-format.md`。

### 4.2 兼容格式：FreeMind（.mm）

```xml
<map version="1.0.1">
  <node TEXT="根主题">
    <node TEXT="一级主题"/>
  </node>
</map>
```

- **读**：宽容解析，只取 `TEXT` 标题与嵌套；`FOLDED`/`POSITION`/`LINK` 等视觉属性忽略；属性名大小写不一（`TEXT`/`Text`/`text`）。
- **写**：用最小骨架 `<map version="1.0.1">` + 递归 `<node TEXT="...">`，每个节点一行或缩进嵌套均可（前端宽容解析）；只写 `TEXT` 属性，不写视觉属性。
- 详见 `freemind-format.md`。

### 4.3 提取来源：Markdown / 文本（树状知识）

```markdown
# 根主题

## 一级主题

### 二级主题
```

- 映射：`#` 级别 = 树层级；`##`/`###`… 逐级缩进；列表项（`-`/`1.`）可映射为同层节点或子节点（`- [ ]` 勾选视作任务子节点）。
- 正文段落择优并入最近节点 `note`。
- Markdown 是线性文档：**读取时先提树，再按需落盘为 .opml/.mm**。

### 4.4 兼容来源：JSON（树）

```json
{ "text": "根", "children": [ { "text": "子" } ] }
```

### 4.5 通用树状知识（目录/嵌套列表等）

- 目录结构、嵌套列表、XML/HTML 层级等一切树状数据：先归一为树模型，再按需映射为 .opml/.mm。

## 5. 树操作语义（增/删/移/合并/编辑）

| 操作 | 语义 |
|---|---|
| 增 | 在指定父节点下追加子节点，或在指定兄弟后插入；新节点默认无 note/color |
| 删 | 移除节点**及其整棵子树**（提示用户确认影响范围） |
| 移 | 节点及其子树整体移动到新父节点下，**保持子树内部顺序不变** |
| 合并 | 同义/重复节点合并：子节点并入保留节点，删除被合并者 |
| 编辑 | 仅改 `text`/`note`/`color`，不动结构（children 不变） |

移动/合并时注意：目标父节点不能是该节点的后代（防成环）。

## 6. 使用原则

1. **先树后格式**：任何修改先在树模型完成，再一次性序列化写出，避免在 XML 文本上打补丁。
2. **结构优先**：`text` 是唯一结构语义；note/color/images 是增强，不影响层级。
3. **完整落盘**：写 .opml/.mm 时保留全部节点（含 note/color），不丢弃前端会展示的信息。
4. **读旧兼容**：读取 .mm/.opml 时先归一到树模型，再做总结、转换或编辑。
5. **主题判定**：新建时根主题 = 用户意图/文档主题；总结解析时根主题 = 文件 `<head><title>` 或 `<map>` 根节点。
