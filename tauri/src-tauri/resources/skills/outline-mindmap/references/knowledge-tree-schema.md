# Knowledge Tree Schema（知识树模型 · AI 内部思维语言）

> 本文件定义「知识树」——大纲与思维导图的统一抽象模型。
> **所有操作先在树模型上构建/修改，再映射为持久化格式（默认 OPML）。禁止直接以 XML 思维拼装文件。**

## 1. 概念

知识树 = 有根有向树：

- 一个根节点（整棵树的主题）；
- 根下若干子节点，节点可无限嵌套；
- 每个节点只有唯一父节点；节点顺序有意义（同级按书写顺序展示）。

大纲（OPML 视图）与思维导图（jsMind 视图）是**同一棵树的两种可视化**，数据结构完全一致。

## 2. 节点模型（JSON）

```json
{
  "text": "节点标题",
  "note": "备注/说明（可选，支持 Markdown）",
  "color": "blue",                 // 可选：视觉标记（blue/green/orange/red/purple）
  "images": ["相对路径或链接"],      // 可选：节点配图
  "children": [ ...子节点递归... ]
}
```

字段约定：

| 字段 | 必填 | 说明 |
|---|---|---|
| `text` | 是 | 节点标题（唯一结构语义字段，尽量短而准确） |
| `note` | 否 | 备注正文，可含 Markdown（如 `- 要点`、表格、代码块） |
| `color` | 否 | 仅视觉标记，**不承载结构语义**（结构只由 text/children 决定） |
| `images` | 否 | 配图（前端相对知识库路径或外链） |
| `children` | 否 | 有序子节点数组 |

## 3. 层级语义

- 树的深度 = 缩进层级 = 思维导图层级 = OPML 嵌套深度。
- 根主题 → 一级主题 → 二级主题 → …… 同级节点之间是并列/分类关系，上下级是包含/从属关系。
- 分类要正交：同一父节点下的子节点应是同一维度（如"技术栈"下不再混入"日程"）。

## 4. 多格式映射（持久化）

### 4.1 默认格式：OPML（.opml）

```xml
<opml version="2.0">
  <head><title>根主题</title></head>
  <body>
    <outline text="一级主题">
      <outline text="二级主题"/>
      <outline text="二级主题" note="备注"/>
    </outline>
  </body>
</opml>
```

映射规则：`text` → `text` 属性；`note` → `note` 属性；`color` → `COLOR` 属性；`images` → `_images` 属性；`children` → 嵌套 `<outline>`。
完整规约（含转义与前端解析器一致性）见 `opml-format.md`。

### 4.2 兼容格式：Markdown（.md）

```markdown
# 根主题

## 一级主题

### 二级主题
```

映射规则：`#` 级别 = 树层级；`#` 一级之下用 `##`/`###`… 逐级缩进；列表项（`-`/`1.`）可映射为同层节点或子节点（含勾选 `- [ ]` 视作任务子节点）。Markdown 是线性文档，**读取时先提树，再按需落 OPML**。

### 4.3 兼容格式：FreeMind（.mm，只读为主）

```xml
<map version="1.0.1">
  <node TEXT="根主题">
    <node TEXT="一级主题"/>
  </node>
</map>
```

`.mm` 属性风格多样（`TEXT`/`TEXT` 大小写、`FOLDED`、`POSITION`、`LINK` 等），**读取时宽容解析，写出一律用 OPML**（前端可另存为 .mm）。

### 4.4 兼容格式：JSON（树）

```json
{ "text": "根", "children": [ { "text": "子" } ] }
```

## 5. 树操作语义（增/删/移/合并/编辑）

| 操作 | 语义 |
|---|---|
| 增 | 在指定父节点下追加子节点，或在指定兄弟后插入；新节点默认无 note/color |
| 删 | 移除节点**及其整棵子树**（提示用户确认影响范围） |
| 移 | 节点及其子树整体移动到新父节点下，**保持子树内部顺序不变** |
| 合并 | 同义/重复节点合并：子节点并入保留节点，删除被合并者 |
| 编辑 | 仅改 `text`/`note`/`color`，不动结构（children 不变） |

移动/合并时注意：目标父节点不能是该节点的后代（防成环）。

## 6. 使用原则

1. **先树后格式**：任何修改先在树模型完成，再一次性序列化写出，避免在 XML 文本上打补丁。
2. **结构优先**：text 是唯一结构语义；note/color/images 是增强，不影响层级。
3. **完整落盘**：写 OPML 时保留全部节点（含 note/color），不丢弃前端会展示的信息。
4. **读旧兼容**：读取 .mm/.opml 时先归一到树模型，再做后续操作。
