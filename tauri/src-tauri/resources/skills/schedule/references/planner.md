# AI 时间规划工作流（schedule 工具扩展动作）

本文档说明 `schedule` 工具 5 个 AI 增强动作的完整工作流与输出规范。
确定性计算（时间排布、统计、归类）由 Rust 引擎完成；目标理解、任务拆解、结论与建议由 AI 生成。

---

## 1. plan —— 任务规划排期（只建议，不创建）

用户表达目标/任务/计划（如"下周完成知识库优化"）时：

1. **AI 拆解目标**为带预估小时数的任务（不要只创建一个笼统日程）：
   ```json
   { "goal": "知识库优化", "deadline": "2026-09-01",
     "tasks": [
       { "title": "RAG 优化", "hours": 4 },
       { "title": "Embedding 测试", "hours": 3 },
       { "title": "UI 调整", "hours": 5 },
       { "title": "测试", "hours": 3 }
     ] }
   ```
2. **调用 `plan`**：`action=plan`、`deadline`、`tasks`（可传 `work_start`/`work_end` 调整工作窗口，默认 9-18；`skip_rest_days` 默认跳过休息日）。
3. **引擎返回**按 deadline 前的空闲时段排布建议（任务不跨天、自动跳过冲突与休息日）。
4. **向用户展示排布建议并询问确认**，确认后逐条 `schedule.add`（`event_type=task`，可带 `ai_estimated_hours`）。

注意：`plan` 返回 `None` 的任务 = deadline 前排不下，如实告知用户并建议拆分或延后截止，不要擅自创建。

## 2. optimize —— 时间效率分析

用户要求分析/优化时间时：

1. **调用 `optimize`**（可选 `range`，默认最近 7 天）。
2. **引擎返回确定性统计**：总投入、会议/深度工作占比、按类型与按天分布、下午会议占比。
3. **AI 基于统计生成发现与建议**，例如：
   ```markdown
   时间分析（过去 7 天）：
   - 会议 15 小时，深度工作 20 小时
   - 发现：下午连续会议过多（下午会议占会议总量 70%）
   - 建议：每天 09:00-11:30 设为深度工作时间（type=focus），
     会议尽量安排在 14:00 之后
   ```
4. 若用户同意，可用 `focus` 创建深度工作时间块、用 `add` 调整会议。

## 3. review —— 日程复盘

用户要求复盘某日/今日时：

1. **调用 `review`**（可选 `date`，默认今天）。
2. **引擎返回**当日已完成/进行中/未开始事件及总投入时长。
3. **AI 结合上下文生成复盘**（延期原因、改进建议），例如：
   ```markdown
   今日总结：
   - 完成：✅ MCP 开发、✅ Skill 优化
   - 延期：❌ UI 优化
   - 原因：下午会议过多，挤压了开发时间
   - 建议：明天减少上午会议，把深度工作前置
   ```

## 4. focus —— 专注时间块

用户要求专心做某事（如"我要专心写代码两个小时"）时：

- **用户给了开始时间**：`focus` `duration_minutes` + `start`，引擎校验冲突后直接创建 `type=focus` 事件。
- **用户未给开始时间**：`focus` `duration_minutes`（+ `task` 标题），引擎推荐下一个可安排时间段；**推荐不自动创建**，向用户确认后调用 `focus`（带 `start`）或 `add`（`event_type=focus`）。
- 建议将深度工作放在精力最好的时段（如上午）；`ai_energy=deep_work`。

## 5. today_plan —— 今日/明日计划

用户要求"今日计划/明日计划/我今天做什么"时：

1. **调用 `today_plan`**（可选 `date`，默认今天；可传 `work_start`/`work_end`）。
2. **引擎返回**：当日日程列表（含类型）+ 工作窗口空闲段。
3. **AI 基于日程与空闲段给出今日安排建议**（如"上午 9:30-11:30 空闲，适合安排深度工作；下午 2 点会议前有 1 小时可处理杂事"）。

---

## 通用约束

- 所有时间计算、冲突检测、节假日判断均以引擎输出为准，AI 不自行推算时间。
- 涉及创建/修改/删除的写操作必须经 `schedule.add` / `update` / `remove`，且删除/覆盖前先确认。
- 冲突时只建议备选方案，绝不自动覆盖、自动删除、自动移动已有日程。
