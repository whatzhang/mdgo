# 文档解析与索引管线（Plan B v2）功能说明

> 面向使用者与维护者，说明**升级后系统的实际行为**：支持哪些格式、点开会发生什么、索引生命周期怎么走、三种"过期/跳过/部分"提示各是什么意思、出问题怎么查。
> 架构与决策依据见 `文档解析管线升级方案（anydoc + pdf-inspector）.md`；逐项验收步骤见 `Plan B v2 验收测试用例.md`。

---

## 1. 一句话总览

**一个文件从进入知识库到被检索到，只经过一条通路：**

```
文件字节
  → DocumentLoader（唯一入口；PDF 走 pdf-inspector，Office/ODF/RTF/EPUB 走 anydoc，其余直读）
  → 统一的 Markdown/文本正文 + 页码 provenance
  → 按「内容形态」选择分块器（Markdown 家族复用 comrak AST 语义分块）
  → 向量 + BM25 → 落 LanceDB / tantivy
```

**索引与预览共用同一个 loader**，因此"搜索到的内容"与"点开看到的内容"必然一致；转换结果另有内容哈希缓存，二次索引不重复解析。

## 2. 支持哪些格式

注册表是**唯一真源**（`core/document/filekind.rs`）。前端能打开的范围由测试强制等于注册表可索引范围（见 §7）。

### 2.1 需要转换的格式（二进制容器）

| 格式 | 扩展名 | 转换器 | 产物形态 | 前端预览方式 |
|---|---|---|---|---|
| **PDF** | `pdf` | pdf-inspector 1.19.0 | Markdown（逐页） | 原生 PDF 查看器（pdf.js） |
| **Word** | `doc` `docx` `docm` | anydoc 0.2.4 | Markdown | 后端转换预览（只读） |
| **PowerPoint** | `ppt` `pps` `pot` `pptx` `pptm` `ppsx` `ppsm` | anydoc | Markdown | 后端转换预览（只读） |
| **Excel** | `xls` `xlsx` `xlsm` `xlsb` | anydoc | Markdown | **`xls`/`xlsx` 走原生表格渲染**；`xlsm`/`xlsb` 走后端转换预览 |
| **OpenDocument** | `odt` `ods` `odp` | anydoc | Markdown | 后端转换预览（只读） |
| **RTF / EPUB** | `rtf` `epub` | anydoc | Markdown | 后端转换预览（只读） |

> 共 **19** 个扩展名走 anydoc。这些格式一律标记 `binary = true` —— 意味着**禁止按 UTF-8 直读**（旧版本正是因为直读它们才出现乱码）。

### 2.2 直读格式（文本类）

| 类别 | 扩展名 | 分块方式 |
|---|---|---|
| **Markdown 家族** | `md` `markdown` `mdown` `mdx` `rst` | AST 语义分块（`doc_like` 的解析 frontmatter：`md`/`markdown`/`mdown`/`rst`；`mdx` 刻意不解析以保持旧行为） |
| **HTML** | `html` `htm` | HTML 分块（可选按目录黑名单当作文档） |
| **大纲/思维导图** | `opml` `mm` | 树形分块（带节点路径） |
| **纯文本** | `txt` | 纯文本分块 |
| **代码（带语言分隔符表）** | `py` `rs` `go` `js` `ts` `jsx` `tsx` `java` `c` `cpp` `h` `hpp` `cs` `swift` `kt` `php` `rb` `sh` `bash` `zsh` `lua` `sql` `r` `scala` `dart` | 代码感知分块（按符号边界） |
| **代码（无分隔符表）** | `bat` `cc` `cmd` `vue` `svelte` `astro` `gradle` `graphql` `gql` `proto` | 纯文本分块（但仍计入"代码"意图） |
| **配置** | `yaml` `yml` `toml` `conf` | 纯文本（计入"代码"） |
| **结构化文本** | `json` `xml` `ini` `cfg` `properties` | 纯文本 |
| **表格数据** | `csv` `tsv` `jsonl` | 纯文本 |
| **样式/脚本** | `ps1` `css` `scss` `less` | 纯文本 |
| **无扩展名约定文件** | `Dockerfile` `Makefile` `GNUmakefile`（按**文件名**匹配） | 纯文本 |
| **带点形式** | `api.dockerfile` `x.makefile` | 纯文本 |

### 2.3 明确不支持

| 格式 | 原因 |
|---|---|
| `.wps`（WPS Office） | 需自行嗅探内容，本版不支持（决策 Q3） |
| 隐藏文件（`.` 开头）与 `*.log` | 被忽略规则统一排除（`IgnoreMatcher`），登记会造成"死配置" |
| OCR（扫描件正文） | 本版不做（决策 Q5）；扫描件**会被明确报告**而非静默丢弃 |

## 3. 点开一个文件会发生什么

前端按扩展名分发，顺序如下（**转换类分支在通用兜底之前**，这是关键）：

| 文件类型 | 行为 |
|---|---|
| `.md` 及 Markdown 家族 | 渲染 Markdown；**可编辑** |
| `.html` | 渲染 HTML |
| `.pdf` | 原生 PDF 查看器 |
| `.csv` | 表格渲染 |
| `.xlsx` / `.xls` | 原生表格（SheetJS） |
| `.json` / `.opml` / `.mm` / `.drawio` / `.excalidraw` / `.puml` / `.canvas` / `.mmd` | 各自的专用渲染器 |
| **19 个 anydoc 格式** | **后端转换预览**：把文件路径交给后端 → 后端用同一个 `DocumentLoader` 转换 → 前端按 Markdown 渲染 |
| 图片 / 视频 / 原始格式 | 各自的查看器 |
| 其余已登记文本 | 进入编辑器（可编辑） |

### 3.1 后端转换预览的行为细节

- **只传路径，不搬字节**：前端不把文件读进 JS 再传回，避免大 `.pptx`/`.xlsb` 双倍搬运。
- **只读**：这类文件**不提供**编辑/保存按钮，也**不会**进入代码编辑器——从设计上杜绝"把 `.docx` 覆盖成 Markdown 文本"。
- **"放映/演示"也关闭**：该功能会回退去读原始字节，对二进制文件无意义。
- 正文超过 **20 万字符**时截断，并在顶部提示"（内容过长，仅预览前 20 万字符）"。
- 预览与索引共用同一缓存，因此**刚索引过的文件打开预览不会重新解析**。
- 失败时给出**可解释原因**（例：`该文件无法预览：扫描件/图片页需 OCR（第 1,2,3 页，共 3 页）`），而不是空白或乱码。

## 4. 索引生命周期

### 4.1 三种索引操作

| 操作 | 入口 | 作用范围 |
|---|---|---|
| **全量重新索引** | 知识库面板 → "索引选项" → 全量重新索引 | 目录下全部可索引文件 |
| **增量索引** | 同上 → 增量索引 | 仅尚未入库的文件 |
| **按类型重建** | 索引过期提示旁的 `只重建 <类型>` 按钮 | 仅指定的 `source_kind`（见 §5） |

### 4.2 版本失效：什么时候必须重建

索引里记录了每个文件类型**实际使用的转换器身份**（如 `pdf → pdf-inspector@1.19.0`）。当它与当前代码期望的不一致时，该类型被判为过期：

| 情况 | 提示 | 处置 |
|---|---|---|
| **某个转换器升级了**（例：pdf-inspector 换版本） | `⚠️ 以下类型的转换器已更新，需重建索引：pdf` + **两个按钮** | 优先点 `只重建 pdf`（快、其他类型不动）；也可全量重建 |
| **全局分块参数变更**（chunk_size/overlap 等） | `⚠️ 分块参数已变更，请重建索引` | 只能**全量重建**（没有类型信息可依据） |
| **旧索引（本版之前的索引）** | 视为**全部类型过期** | 必须全量重建一次 |

> **升级须知（重要）**：从本版之前的版本升级过来，**第一次必须全量重建**——旧索引没有 `source_kind`/`converter`/页码等列。这一次重建之后，"按类型重建"才真正可用。

**按类型重建的守卫**：若全局分块参数已变更，`只重建 <类型>` 会**拒绝执行**并提示先做全量重建——避免新旧分块口径混库。

### 4.3 增量索引与"过期类型"

某类型已过期时，**增量索引不会写入该类型的文件**（避免把新转换器产物混进旧索引）；这些文件会在你重建该类型后被处理。

## 5. 三种"没进库"的提示怎么读

知识库面板的健康度区域下会列出诊断。**两类必须分开理解**：

| 提示 | 含义 | 用户该做什么 |
|---|---|---|
| `未入库文件 N 个（整文件未进入索引，搜索不到）` | **整个文件**没进库：扫描件、加密、超限、解析失败等 | 按给出的原因处理；扫描件需 OCR（本版不做） |
| `部分索引文件 N 个（已入库，但下列页未进库）` | 文件**已经能搜到**，只有列出的那几页没进 | 通常无需处理；若那几页关键，需 OCR |

每条记录包含：**文件路径 + 原因 +（涉及页码）**。例：

```
⚠️ 未入库文件 1 个（整文件未进入索引，搜索不到）
· scan.pdf — 扫描件/图片页需 OCR（第 1,2,3 页，共 3 页）

⚠️ 部分索引文件 1 个（已入库，但下列页未进库）
· mixed.pdf — 跳过 第 4 页 / 共 6 页：该页无可提取文本
```

**这些记录是持久的**：写进知识库的索引元数据，任何时候打开面板都能看到（不只在索引当次可见）。一次增量索引**不会**清空其他文件的历史诊断（只有被重新处理过的文件其记录才会刷新/消失）。

### 5.1 常见跳过原因对照

| 原因码 | 中文含义 | 处置 |
|---|---|---|
| `needs_ocr` | 扫描件/图片页需 OCR | 本版不做 OCR；如需检索请先自行 OCR 成带文字层的 PDF |
| `encrypted` | 文档加密 | 解密后重新索引 |
| `too_large` | 超过 200MB 上限 | 拆分文件 |
| `too_small` | 有效内容不足（小于最小阈值） | 正常，忽略 |
| `empty_content` | 提取成功但无内容 | 检查文件是否真的有文字 |
| `not_utf8` | 文本文件不是 UTF-8 | 转码为 UTF-8 |
| `malformed` | 结构损坏 | 用对应软件重新另存 |
| `missing_part` | 缺少必要部件 | 同上 |
| `unsupported` | 未登记格式 | 见 §2.3 |
| `io` | 读取失败（权限/占用） | 检查权限，确认文件未被独占 |

## 6. 检索侧行为

| 能力 | 说明 |
|---|---|
| **页码 provenance** | 来自 PDF 的 chunk 带 `page_start`/`page_end`/`source_spans`。**页码是溯源，不是分块边界**——一个块可以跨页（此时 `page_end > page_start`）。命中即可给出"第 N 页"或"第 N–M 页" |
| **表格表头列名** | 表格块额外带表头列名 metadata（供按列名检索/展示）。列名**不进入向量文本**，避免稀释正文语义；但表头行本来就在正文里，所以关键词检索本就能命中列名 |
| **意图过滤** | 查询被路由到 Code/Document/Outline/General 意图，各意图有扩展名白名单，白名单由注册表能力位派生 |
| **类型分布图** | 按注册表分类统计。**注意**：`jsx/tsx/cs/swift/kt/bash/zsh/r/scala` 由"其他"改为归入"代码"（它们本来就由代码分块器处理，属修正统计口径） |
| **RAG / 文档问答** | 资料白名单来自注册表（Markdown/文本类）。**已登记格式转换失败时报错**，不会把原始字节按乱码喂给模型；**未登记**格式（如 `.log`）保持旧的宽松读取行为 |

### 6.1 Agent 工具：`read` 与 `read_document` 的分工

主 Agent 有两个读文件的工具，**职责按文件类型划分，不重叠**：

| 工具 | 适用范围 | 说明 |
|---|---|---|
| **`read`** | 文本 / 代码类（`.md` `.txt` `.json` `.csv` `.yaml` 代码…） | 直接按 UTF-8 读取，支持 `path`/`paths` 并行与 `offset` 分页 |
| **`read_document`** | **二进制文档**：PDF、Word（`doc`/`docx`/`docm`）、PowerPoint（`ppt`/`pptx`/`pptm`/`pps`/`ppsx`/`ppsm`/`pot`）、Excel（`xls`/`xlsx`/`xlsm`/`xlsb`）、OpenDocument（`odt`/`ods`/`odp`）、RTF、EPUB | 经 **`DocumentLoader`** 转换成 **Markdown** 后返回；支持 `offset` 分页 |

**为什么必须分开**：这些格式是 ZIP/OLE 容器，按文本直读只会得到乱码。旧行为下 `read` 对 `.pptx` 做 lossy 解码，把压缩包字节当正文塞进模型上下文（既无信息量又污染推理）。现在的行为是：

- 用 `read` 读二进制文档 → **明确拒绝**并指路：`xxx.pptx 是二进制文档（转换器：anydoc），不能按文本直读。请改用 read_document 工具读取其文本内容（它会转换成 Markdown）。`
- 用 `read_document` 读文本文件 → 也会明确拒绝并引导回 `read`（两个工具不互相兜底，避免模型乱试）。
- 用 `grep` 搜内容时，二进制文档**无法被搜索**（这是文本检索的固有限制）。此时结果里会附注：`（注：本次有 N 个文档文件是二进制格式…若需查看其中内容，请用 read_document 读取该文件）`——防止模型把"grep 没找到"误判成"文件里没有这个内容"。

**`read_document` 的输出形态**：

```
[文档] 资料/产品介绍.pptx ｜ 转换器=anydoc@0.2.4 ｜ 来源类型=office ｜ 形态=markdown

## 第一页标题
...转换后的 Markdown 正文...
```

- 元信息行说明"这份文本怎么来的"（转换器 / 来源类型 / 形态 / 页数），也是排查转换问题的线索。
- 若文档有部分页无法提取（扫描页），会附 `[注意] 该文档有 N 页无法提取文本（第 X 页）`。
- 若转换器有提示（如版面复杂、字体编码问题），附 `[转换提示] …`。
- 超过 8192 字符时给出续读指引（`offset=`），与 `read` 的分页语义一致。
- 扫描件 PDF 会**明确告知需要 OCR**，而不是返回空白或乱码。

## 7. 跨层一致性（维护者须知）

**后端注册表是唯一真源**，但三份前端文件仍各持一份扩展名清单（`main.html` 是 App 实际构建的入口；`index.html`/`index_cdn.html` 为冻结副本，不随本次修改）。为防止再次漂移，有一条单测强制以下不变式：

1. `CONVERTED_DOC_EXT_SET`（前端走后端转换预览的集合）⊆ `DOC_EXT_SET`
2. `CONVERTED_DOC_EXT_SET` = 注册表 Office 全集 − `{xls, xlsx}`
3. `support.js::CONVERTED_DOC_RE` 与 `CONVERTED_DOC_EXT_SET` 逐项相等
4. `_EXT_TYPE_MAP` 覆盖每个 Office 扩展名
5. **注册表扩展名 ∪ `DOC_FILE_NAMES` ⊆ 前端可打开集合**

**改格式支持时，只改注册表是不够的** —— 第 5 条会拦住遗漏；请按提示补齐前端清单，别绕过测试。

## 8. 性能与缓存

| 机制 | 说明 |
|---|---|
| **转换缓存** | 主键 = SHA-256(文件字节) + 转换器 id + 转换器版本 + 选项指纹。同一文件内容未变则直接还原，**不重新解析**。直读类文本不缓存（本身极快，哈希反而是开销） |
| **前置尺寸护栏** | 读盘**之前**先用文件大小挡掉超限文件（`max_file_bytes = 200MB`），避免把大文件读进内存 |
| **缓存位置** | `{知识库}/.mdgo/conversion_cache.sqlite`，条目上限 20000（超出按最旧裁剪）。可安全删除，删后自动回退为重新解析 |
| **embedding 缓存** | 独立的既有机制，位置同目录 |

## 9. 故障排查

| 症状 | 可能原因 | 处置 |
|---|---|---|
| **问 Agent 某个 PPT/PDF 的问题，它答不出/说读不了** | 旧版本没有读二进制文档的工具 | 本版已新增 `read_document`：Agent 会自行调用。若仍失败，看它是否明确说明了原因（需 OCR / 加密 / 损坏） |
| Agent 用 `read` 读 `.pptx` 报"是二进制文档" | **这是预期行为**（防乱码），不是故障 | 无需处理；Agent 会改用 `read_document`。若它反复重试，说明模型未遵循引导，看日志里两次调用之间有无报错 |
| Agent 说"文件里没有某内容"，但你知道有 | 该文件是二进制文档，`grep` 无法搜索其内容 | 结果里会附注提示；让 Agent 用 `read_document` 读取该文件 |
| 点开 Office 文件显示"文件类型不支持" | 前端可打开集合漏了该扩展名（不应发生，有测试守卫） | 跑 `cargo test --lib frontend_ext_tables_match_registry` 看是否报出该扩展名 |
| 点开某个文件显示乱码 | 该扩展名**未登记**因而走了直读兜底 | 检查是否在注册表内；未登记格式应改为用对应软件另存为已支持格式 |
| 文件明明有内容却搜不到 | 整文件未入库（见 §5 诊断） | 看面板"未入库文件"里的原因 |
| 搜索结果里的 PDF 点开定位不到页 | 该命中来自 BM25 单独召回（BM25 schema 不存 provenance） | 已知限制；向量路命中带页码 |
| 升级后提示"分块参数已变更" | 首次升级到本版 | 做一次全量重建（见 §4.2） |
| 升级后提示某类型转换器已更新 | 该类型的转换器版本变了 | 点 `只重建 <类型>` |
| 索引后统计数字对不上 | 类型分布口径调整（§6） | 属预期变化 |
| 二次索引仍很慢 | 转换缓存被删/未命中；或瓶颈在 embedding | 看 `{知识库}/.mdgo/conversion_cache.sqlite` 是否存在 |
| 构建失败：`no variant ... StringLiteral` | `lopdf` 补丁被移除或未生效 | 见 §11 |

## 10. 本版与旧版的行为差异（升级清单）

1. **首次升级必须全量重建一次**（原因见 §4.2）。
2. **新支持 19 个格式**（Word/PowerPoint/Excel 变体、ODF、RTF、EPUB）——旧版这些是"在册但无提取器"的幽灵条目或直接不支持。
3. **PDF 改为 pdf-inspector**：有结构（标题层级）、有页码、扫描件不再静默为空而是明确报告。
4. **曾"能搜到却点不开"的扩展名修好**：`markdown`/`mdown`/`mdx`/`tsv`/`cfg`/`makefile`/`gnumakefile`。
5. **类型分布图变化**：9 个代码类扩展名从"其他"归入"代码"。
6. **新增诊断面板**（§5）与**按类型重建**（§4.2）。
7. **转换缓存**：二次索引明显更快。
8. `index.html` / `index_cdn.html` **未同步**（冻结副本，仅 `main.html` 是 App 入口）。

## 11. 构建依赖说明（维护者须知）

`Cargo.toml` 里有一个**临时**补丁：

```toml
[patch.crates-io]
lopdf = { git = "https://github.com/J-F-Liu/lopdf", rev = "a15329d0…" }
```

- **为什么需要**：`tantivy 0.26` 要求 `time ^0.3.47`，而 `time 0.3.47` 改了 `FormatItem` 的变体名；`pdf-inspector ≥1.18.0` 依赖的 `lopdf ^0.44.0` 仍在引用旧名 → 不补丁则 `lopdf` 编译失败（上游 issue #518）。
- **为什么不能靠别的方式绕开**：不能降 `time`（tantivy 下限）；不能升 `lopdf` 到 0.45（`^0.44.0` 不接受）；不能从下游关闭 lopdf 的 `time` feature（Cargo feature 是并集，只有 lopdf 的**直接**依赖方能关闭）。
- **为什么没有选择"降级 pdf-inspector 以删掉补丁"**：那是**唯一**能删补丁的路径（`≤1.17.0` 用 `lopdf ^0.42.0`），但能力不等价——`1.17.0 → 1.19.0` 是 +11053/−1392 行，缺失 `xref_repair`（可恢复一类**否则整篇打不开**的 PDF）、过期 CMap 修复（中日文乱码）、资源上限加载以及多个抽取器模块。**决策：保留补丁、留在最新版**。详见 `Cargo.toml` 内注释与方案文档 §0.3「依赖决策复核」。
- **影响**：首次构建 / CI / 离线镜像需能访问 GitHub 拉取该 rev。
- **移除条件**：`pdf-inspector` 依赖 `lopdf ≥0.45` 后删除补丁（`lopdf 0.45.0` **已发布**）。
- **如果 GitHub 可达性成为硬约束**：可把修复版 lopdf 源码 vendor 进仓库，改用 `[patch.crates-io] lopdf = { path = "vendor/lopdf" }` —— 同样不损失能力。
