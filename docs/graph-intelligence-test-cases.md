# 知识图谱智能功能 —— 测试人员测试手册

> 适用版本：本次会话交付的知识图谱智能功能（后台 AI 抽取流水线 / 图谱问答 / 经验库）。
> 阅读对象：**测试人员**。本文按「业务功能」组织，给出可执行的黑盒测试步骤与预期结果，
> 不依赖代码内部实现。自动化回归基线见 §8（测试人员可一键运行确认交付未破坏既有功能）。

---

## 1. 测试概述

### 1.1 被测业务功能（本次交付）

| 功能 | 一句话说明 | 用户入口 |
|---|---|---|
| F1 后台 AI 抽取流水线 | 图谱构建后自动对高价值文档排队做智能抽取（免费规则 + 可选 LLM），无需人工逐篇点「抽取」 | 图谱页 → 侧栏「待确认」（查看产物） |
| F2 图谱问答（GraphRAG） | 用自然语言提问，返回答案 + 可追溯的证据（可一键定位到原文段落） | 图谱页 → 侧栏「AI 分析 → 问答」 |
| F3 经验库 | 记录"问题→解决方案"经验（Git 提交/AI 操作事件），可按问题检索历史解法 | 图谱页 → 侧栏「AI 分析 → 经验」 |
| F4 既有功能回归 | 侧栏 13 个既有动作、5 种视图、LOD 缩放、节点详情等 | 图谱页全界面 |

### 1.2 测试环境准备（前置条件，全部用例共用）

1. **测试知识库**：准备一个含 10+ 篇 Markdown 文档（含互相链接、含外部链接如 `https://redis.io`）的目录作为知识库。
2. **触发图谱构建**：在应用中打开该知识库并完成全量索引（或图谱页执行刷新/重建）。
3. **可选 LLM 配置**（F1-LLM / F2 完整路径用）：在应用设置中填写 LLM 端点与模型；不配置时验证降级路径。
4. **可选本地 Embedding**（语义聚类/相似边/问答混合检索用）：确认本地模型已就绪（应用有提示）。
5. **观察日志**：后台日志关键字 `[graph]` / `[graph-worker]`，用于验证后台流水线行为。

### 1.3 测试结果判定约定

- 每用例给出「步骤 → 预期」；预期全部满足 = 通过。
- 标注 ⚠ 的步骤为**可选**（依赖 LLM/Embedding 配置），未配置时执行降级分支验证。

## 2. 功能 F1：后台 AI 抽取流水线（构建后自动排队 + 智能抽取）

> 核心价值：用户什么都不用点，图谱构建后系统自动按"重要度"排队抽取文档关系，
> 产物进入「待确认」列表（置信度 ≥0.9 自动确认落图）。

### TC-F1-01 构建后自动入队（正常路径）

| 项 | 内容 |
|---|---|
| 优先级 | P0 |
| 前置 | 1.2 环境就绪；知识库此前未构建过（或清空图数据） |
| 步骤 | ① 触发全量构建（打开知识库并完成索引）→ ② 观察日志 → ③ 侧栏点「待确认」 |
| 预期 | ② 日志出现 `[graph] AI 队列已更新（N 个文档）`（N≈文档数）；③ 若存在候选，「待确认」列表展示 AI 关系（来源实体、关系类型、置信度、证据摘录、确认/忽略按钮）；若无可展示，提示先运行抽取 |
| 备注 | 队列处理是后台周期任务（启动约 20s 后开始，每 30s 一轮），请等待 1-2 个周期再断言 |

### TC-F1-02 高价值文档优先处理（重要度排序）

| 项 | 内容 |
|---|---|
| 优先级 | P1 |
| 前置 | 知识库含：README.md（或含"设计/方案/架构/总结"字样的文件）+ 被多处引用的文档 + 近期修改的文件 + 冷门文档 |
| 步骤 | ① 构建后观察日志（`[graph-worker]` 处理顺序）或对比「待确认」候选来源文档 |
| 预期 | 被引用多 / 文件名高价值 / 近期改动的文档**先**被处理；冷门文档后处理或暂未处理 |
| 备注 | 重要度 = 引用度(50%) + 新鲜度(30%) + 文件名(20%)；同一批每轮最多 3 篇 |

### TC-F1-03 规则抽取兜底（未配置 LLM）

| 项 | 内容 |
|---|---|
| 优先级 | P0 |
| 前置 | **不配置** LLM；知识库文档含外部链接（如 `[Redis](https://redis.io)`） |
| 步骤 | ① 构建 → ② 等 1-2 个 worker 周期 → ③ 图谱中搜索 `redis` 等外部站 host 名 |
| 预期 | ③ 出现实体节点（如 `entity:redis`），无需 LLM 也生效（免费规则抽取） |
| 备注 | 该路径不产生 LLM 费用；验证 `graph_metrics` 中 `llm_calls` 未增长 |

### TC-F1-04 LLM 抽取与自动确认（配置 LLM）⚠

| 项 | 内容 |
|---|---|
| 优先级 | P1 |
| 前置 | 配置 LLM；队列中有高价值文档 |
| 步骤 | ① 构建 → ② 等 2-4 个 worker 周期 → ③ 侧栏「待确认」→ ④ 查看 `graph_metrics` |
| 预期 | ③ 出现 LLM 抽取的候选关系（带证据摘录）；置信度 ≥0.9 的候选**自动落图**（不在待确认列表，直接成为正式关系）；④ `llm_calls` 增长 |
| 备注 | 每目录每轮 LLM 抽取最多 2 篇（节流）；抽取内容截断到 4000 字符 |

### TC-F1-05 LLM 失败降级（不阻塞流水线）

| 项 | 内容 |
|---|---|
| 优先级 | P2 |
| 前置 | 配置错误的 LLM（如无效 endpoint） |
| 步骤 | ① 构建 → ② 等 1-2 个周期 → ③ 观察日志与「待确认」 |
| 预期 | ③ 规则抽取照常完成（候选仍产生）；日志有抽取失败告警；`llm_failures` 指标增长；**worker 不崩溃、流水线不中断** |
| 备注 | LLM 硬错误会重试，最多 3 次后该项标记失败并跳过 |

### TC-F1-06 单文件修改后重新入队（增量）

| 项 | 内容 |
|---|---|
| 优先级 | P2 |
| 前置 | 图谱已构建；已有一篇文档被处理过 |
| 步骤 | ① 修改该文档内容（新增外部链接/改标题）→ ② 触发该文件增量更新（应用文件监控自动）→ ③ 等 1-2 个周期 → ④ 检查该文档是否重新抽取 |
| 预期 | ③ 该文档进入处理队列并重新抽取（内容变更强制重处理）；未修改的文档**不**重复处理（幂等） |
| 备注 | 全量重建不会重复处理已完成文档；仅单文件变更触发重抽 |

### TC-F1-07 文件删除后不产生僵尸重试

| 项 | 内容 |
|---|---|
| 优先级 | P2 |
| 前置 | 队列中有未处理文档 |
| 步骤 | ① 删除某未处理文档 → ② 等 1-2 个周期 → ③ 观察日志 |
| 预期 | ③ 日志提示该文件不存在并跳过（标记完成），不无限重试、不报错 |

### TC-F1-08 可观测性指标

| 项 | 内容 |
|---|---|
| 优先级 | P2 |
| 前置 | 已完成 ≥1 次后台处理（含成功与失败路径各一） |
| 步骤 | 调用 `graph_metrics`（或经主应用调试通道） |
| 预期 | 返回含 `worker_processed`（成功数）、`worker_failed`（失败数）、`llm_calls`、`llm_failures`、`candidates_pending`、`candidates_confirmed` 等字段，数值与日志观察一致 |
| 备注 | 前端暂未直接展示该面板，属后端可观测性验证 |

### TC-F1-09 候选确认 / 忽略闭环（回归）

| 项 | 内容 |
|---|---|
| 优先级 | P0 |
| 前置 | 「待确认」列表存在候选 |
| 步骤 | ① 点某候选「确认」→ ② 点另一候选「忽略」→ ③ 重开「待确认」→ ④ 图谱查看 |
| 预期 | ① 确认后该关系成为正式边（图谱可见），计数减少；② 忽略后不再出现，相关边被移除；③ 列表只含剩余候选；④ 确认/忽略均不报错 |
| 备注 | 涉及既有功能，确认后台流水线产物可正常走人工审核闭环 |

## 3. 功能 F2：图谱问答（GraphRAG）

> 用户入口：图谱页 → 侧栏「AI 分析 → 问答」。

### TC-F2-01 提问与回答（配置 LLM）⚠

| 项 | 内容 |
|---|---|
| 优先级 | P0 |
| 前置 | 配置 LLM；知识库含对应主题文档（如 Redis） |
| 步骤 | ① 点「问答」→ ② 输入"Redis 的持久化方案有哪些？"→ ③ 点「提问」（或回车） |
| 预期 | ③ 显示回答文本（含图实体识别与证据引用，200 字内、条理清晰）；下方出现证据列表（来源文档 + 摘录，最多 8 条） |
| 备注 | 空输入不发起请求 |

### TC-F2-02 回答降级（未配置 LLM）

| 项 | 内容 |
|---|---|
| 优先级 | P1 |
| 前置 | **不配置** LLM；知识库有可命中实体 |
| 步骤 | ① 提问 → ② 观察 |
| 预期 | ② 显示"未配置 LLM：以下为图证据而非 AI 回答"提示，并列出检测到的实体与图关系/相关文档（降级回答，不报错） |

### TC-F2-03 证据定位到段落（chunk 定位）

| 项 | 内容 |
|---|---|
| 优先级 | P0 |
| 前置 | 问答返回带「定位段落」按钮的证据（需文档已建 chunk 内容层） |
| 步骤 | ① 点证据条目的「定位段落」 |
| 预期 | ① 图谱聚焦到该证据对应的语义块（chunk 节点）：节点被选中高亮、相机定位、右侧详情显示该段落内容；若当前缩放级别低于细粒度，自动提升到细粒度视图（LOD 徽标更新） |
| 备注 | 这是"证据可追溯、可跳原文"的核心验收点（PRD §47） |

### TC-F2-04 打开证据源文档

| 项 | 内容 |
|---|---|
| 优先级 | P1 |
| 前置 | 问答返回无 chunk 定位的证据（图关系证据）或文档证据 |
| 步骤 | ① 点击证据条目的来源文档名 / 无定位按钮时点整条 |
| 预期 | ① 主应用打开对应源文档（文件定位） |
| 备注 | 图关系证据（无文档路径）不可点击打开，仅展示关系文本 |

### TC-F2-05 失效证据容错

| 项 | 内容 |
|---|---|
| 优先级 | P2 |
| 前置 | 图谱数据已重建（chunk 节点 id 过期）后仍保留旧问答结果 |
| 步骤 | ① 重建图谱 → ② 在旧问答结果上点「定位段落」 |
| 预期 | ② 提示"该节点不在当前图谱中（可能已重建）"，不报错、不白屏 |

### TC-F2-06 问答失败容错

| 项 | 内容 |
|---|---|
| 优先级 | P2 |
| 前置 | 无任何可用 LLM 且图证据为空（极端场景） |
| 步骤 | ① 提问 → ② 观察 |
| 预期 | ② 面板显示"问答失败"类提示，界面不崩溃，其它侧栏功能仍可用 |

### TC-F2-07 输入安全（XSS）

| 项 | 内容 |
|---|---|
| 优先级 | P1 |
| 前置 | — |
| 步骤 | ① 提问内容或文档证据含 `<script>alert(1)</script>`、引号、HTML 标签 |
| 预期 | ① 均以纯文本展示，无弹窗、无页面注入（转义生效） |

## 4. 功能 F3：经验库

> 用户入口：图谱页 → 侧栏「AI 分析 → 经验」。
> 说明：经验事件当前**无用户界面录入入口**，需经 `graph_experience_record` 命令写入
> （采集源自动化属后续规划，见 `docs/experience-graph-collection-plan.md`）。
> 测试人员可用主应用调试通道调用该命令构造测试数据。

### TC-F3-01 经验事件写入（规则富化路径）

| 项 | 内容 |
|---|---|
| 优先级 | P0 |
| 前置 | **不配置** LLM |
| 步骤 | ① 调用 `graph_experience_record`，事件：source=`git_commit`，title="fix: 修复缓存穿透问题"，body="使用布隆过滤器避免缓存击穿"，file_path="src/cache.rs" → ② 侧栏点「经验」→ ③ 输入"缓存穿透"→ 检索 |
| 预期 | ② 「经验」面板出现输入框（描述问题 → 检索）；③ 返回该经验（problem=修复缓存穿透问题，solution=使用布隆过滤器避免缓存击穿，匹配度>0） |
| 备注 | 规则路径：标题含"修复/解决/优化/重构/问题"等关键词切出 problem；body 首行作 solution |

### TC-F3-02 经验事件写入（LLM 富化路径）⚠

| 项 | 内容 |
|---|---|
| 优先级 | P1 |
| 前置 | 配置 LLM；事件描述不含规则关键词 |
| 步骤 | ① 调用 `graph_experience_record`，title="重构索引模块性能太差"，body="把全量扫描改成倒排索引后查询快了一个数量级" → ② 经验检索"索引性能" |
| 预期 | ① 写入成功（内部 LLM 抽取 P/S，`llm_calls` 增长）；② 检索可命中，且 problem/solution 为 LLM 抽取的结构化文本（非原始标题逐字） |
| 备注 | LLM 失败自动回退规则，不报错（fail-open） |

### TC-F3-03 纯事务型事件不建图

| 项 | 内容 |
|---|---|
| 优先级 | P2 |
| 前置 | — |
| 步骤 | ① 调用 `graph_experience_record`，title="chore: 更新依赖"，body=""（无 P/S 内容）→ ② 图谱中搜索"经验"类节点 |
| 预期 | ② 事件已记录（经验检索不返回它），但**不产生** Problem/Solution/Event 图节点（噪声过滤） |

### TC-F3-04 经验命中跳转文档

| 项 | 内容 |
|---|---|
| 优先级 | P1 |
| 前置 | 已写入带 file_path 的经验（TC-F3-01） |
| 步骤 | ① 经验检索命中 → ② 点击命中条目 |
| 预期 | ② 主应用打开该经验关联的文档（src/cache.rs） |
| 备注 | 无 file_path 的命中条目点击无跳转（无报错） |

### TC-F3-05 经验空结果提示

| 项 | 内容 |
|---|---|
| 优先级 | P2 |
| 前置 | 知识库无任何经验事件 |
| 步骤 | ① 点「经验」→ ② 输入任意问题 → 检索 |
| 预期 | ② 显示"暂无相关经验"类提示（含经验来源说明），不报错 |

### TC-F3-06 经验事件列表

| 项 | 内容 |
|---|---|
| 优先级 | P2 |
| 前置 | 已写入 ≥2 条经验 |
| 步骤 | 调用 `graph_experience_events` |
| 预期 | 返回全部事件（source 为小写枚举：git_commit / ai_operation / chat_message），字段完整（id/title/body/file_path/created_at） |

|---|---|---|

| TC-F4-06 右上角无悬浮 AI 助手 | 检查图谱页右上角 | **无**悬浮 AI 按钮/模态框（此前已按产品决定删除；问答入口仅存在于侧栏「AI 分析」区） |
| TC-F4-07 搜索与收藏 | 搜索关键词；节点详情点 ☆ | 命中节点聚焦；收藏出现在「收藏」列表，可取消 |
| TC-F4-08 语义聚类默认化 | 本地 Embedding 就绪的首次构建 | 自动尝试语义聚类；成功后前端默认展示语义簇；失败保持目录聚类（有日志） |

## 6. 边界与异常场景汇总（负面用例）

| 用例 | 场景 | 预期 |
|---|---|---|
| TC-B-01 | 空知识库（0 文档）构建 | 构建成功、图为空；问答/经验给出空态提示，不崩溃 |
| TC-B-02 | 非 Git 目录（经验采集相关，仅涉及后续采集源） | 当前版本不涉及；采集源落地后验证"跳过且不报错" |
| TC-B-03 | LLM 配置后中途改坏 | 问答显示失败提示；后台流水线规则抽取照常 |
| TC-B-04 | 队列项对应文件被删除（后台） | 标记完成跳过，不无限重试 |
