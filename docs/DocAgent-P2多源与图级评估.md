# DocAgent P2 多源索引与图级问答评估（决策文档）

> 配套 PRD：`docs/PRD-小助手文档Agent.md`（P2-2 多源、P2-5 图级）　归档：`docs/小助手DocAgent-实现归档.md`
> 结论先行：**P2-2/P2-5 在 mdgo 为“远期·按规模启用”项**；本文档给出启用阈值、接入面与优先级，
> 不作为 v1.1 默认启用。P2-1（双向定位）与 P2-3/P2-4 已按“可点定位/全局唤起/记忆注入”落地。

## 1. P2-2 多源索引（本地文件 + 书签 + 剪藏）

现状：mdgo 已有 `bookmark_*`（导入/富化/树/向量检索）与 KB 文件索引两套引擎；`doc_agent_query`
当前仅消费「单文件/选区 + extra_files」。
评估：在 doc 会话中并入书签/剪藏的最优路径是**复用现有 bookmark 检索，而非自建第三套索引**：
- 检索调用点：`commands/bookmark.rs::bookmark_search`（能力已具备），在 `doc_agent_query`
  增加 `include_bookmarks: Option<bool>` 时异步取 top-N，以“【相关书签】标题+摘要+URL”并入 system。
- 剪藏（URL 导入为本地 md）：走既有 bookmark 导入 → 与文件库同索引即可被 `extra_files/[[双链]]` 命中，
  无需新增存储。
- 设计限制：书签命中不注入正文全文（URL 内容多为外部版权），只注入标题/摘要/链接，回答需联网核实时
  再提示使用 webfetch 工具（主 Agent 面）。
启用阈值：书签 > 200 条 或 用户开启“问答含书签”设置时启用；默认关（保持上下文纯净）。

## 2. P2-5 图级问答（LightRAG / GraphRAG 增量路线）

评估结论：mdgo 单库规模以“个人笔记为主”，**当前不满足图建造成本/收益拐点**；PRD 已标注
“文件量触发”。建议按 LightRAG 路线增量启用：
- 触发条件（候选）：索引文件 ≥ 5k 且出现高频“跨文档/全局类”问题（可用 query 意图检测统计）；
- 接入点：新建 `core/docagent` 侧图索引为**可选服务**（新增模块 `core/graphrag/` 或对接外部服务），
  不进 v1.1 主链路；doc 会话在未启用时回答“全局类”问题走现有「按问题选章节 + 关联文件」近似策略，
  并在响应中提示范围边界。
- 对照：GraphRAG 成本高（社区摘要+查询多跳 token 大）；LightRAG 双层检索与增量更新更适合个人库
  （HKUDS/LightRAG 路线），k 与阈值需用 `retrieval_eval` 基线回归。
决策：默认不接入；进入“评估优先级 P1”条件为文件量 ≥5k 或用户调研确认全局问答频次 > 30%。

## 3. 与 PRD 的一致性
- P2-1 双向引用：已通过引用 `[§N]`/`(file:行)` 点击定位 + 编辑器 reveal 实现“回答→原文”；“编辑器选中→
  追问”由选区入口承接（双向链路可用）。
- P2-2/P2-5：按 PRD“远期/按规模启用”语义以本评估 + 接入设计交付，默认不启用（避免重造检索平台）。
- P2-3 全局唤起（Alt+Q）与 P2-4 记忆注入：已实现。

## 4. 建议下一步（若决定推进 P2-2/P2-5 代码化）
1. `doc_agent_query` 加 `include_bookmarks`（复用 bookmark_search），随设置开关；
2. 用 `retrieval_eval` 建立“doc 上下文 + 书签”回归基线；
3. 图级：先在 `docs` 输出 LightRAG 接入设计（schema/增量/成本），达到阈值后再代码化。
