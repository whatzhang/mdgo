# mdgo 知识资产扩展设计定稿（书签导入与富化）

> 最后更新：2026-08-23
> 本文档对应 `tauri/src-tauri/src/core/knowledge/bookmark/`（importer / enrichment / vector / repository / search / tree）与 `commands/bookmark.rs`，为 Bookmark v2.0 简化重构后的设计定稿。

```text

    │   ├─ 组装 embedding 文本：Tags→Category→Title→Summary(截断300字)       │
```

## 设计要点（相对 v1.x 的变化）

1. **单表**：仅 `bookmarks` 一张 SQLite 表；删除 `bookmark_jobs`（队列由
   `status='pending'` 直接驱动）、`bookmarks_fts`（检索用 LIKE 直扫）。
   表位于知识库级统一数据库 `{dir}/.mdgo/mdgo.db`（每知识库独立）。
2. **三态状态（非状态机）**：`pending` / `ready` / `failed`。失败即终态，
   不再重试、不再入向量库；崩溃遗留的 pending 下次 Worker 启动后自动重新处理。
3. **去重规则**：以 `canonical_url` 为键，**已存在直接跳过**（不更新、不重新入队）；
   同一批内重复 URL 也只在内存去重（`HashSet`），计为 skipped。
4. **死链识别（后端）**：抓取阶段失败（HTTP 错误/超时/网络/DNS/SSRF 拒绝）→
   `dead=1` + `status=failed`；列表/树/Agent 详情均带死链标记。
5. **embedding 一致性**：`embedding_text` 列与向量库 `text` 列写入同一字符串；
   文本顺序 Tags 置前 + Summary 截断（300 字），修复 BGE 512 token 截断导致
   向量缺 tags 的问题。
6. **检索目的**：仅 URL + summary + category + tags；raw_content 只服务 LLM 总结
   （入库截断 20,000 字符，LLM 侧使用抓取时的完整 markdown）。
7. **5 万上限**：前端弹提示 + 截断前 5 万条，后端兜底同样截断。
8. **Worker 手动触发**：导入与应用启动均不自动启动 Worker（避免无操作即自动消耗
   LLM）；仅「分析扫描」按钮经 `bookmark_worker_start` 触发，忙态连续处理
   （无 500ms 空转），连续空闲 30s 退出，之后可再次点击重启。
9. **中断影响面收窄**：抓取批上限 32（原 256）、阶段C 分块提交（每块 16 条
   独立 embedding → upsert → ready），中途关闭应用只损失当前块，已提交块保持 ready。
10. 开发阶段，不做旧数据兼容（直接删旧表即可，schema 变更由新库自然生效）。

## 数据表结构（bookmarks）

```sql
CREATE TABLE IF NOT EXISTS bookmarks (
    id             TEXT PRIMARY KEY,
    url            TEXT NOT NULL,
    canonical_url  TEXT NOT NULL UNIQUE,      -- 归一化 URL（去重键）
    title          TEXT,
    browser_folder TEXT,
    added_at       INTEGER,
    source_file    TEXT,
    category       TEXT,                      -- LLM 分类
    summary        TEXT,                      -- LLM 摘要
    tags           TEXT,                      -- LLM 标签（JSON 数组字符串）
    raw_content    TEXT,                      -- 抓取正文（截断 20k 字符，仅用于 LLM 总结）
    embedding_text TEXT,                      -- 实际送入 embedding 的文本（与向量库一致）
    status         TEXT NOT NULL DEFAULT 'pending',  -- pending | ready | failed
    dead           INTEGER NOT NULL DEFAULT 0,       -- 死链标记
    last_error     TEXT,
    revision       INTEGER NOT NULL DEFAULT 1,
    created_at     INTEGER NOT NULL,
    updated_at     INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_bookmarks_status  ON bookmarks(status);
CREATE INDEX IF NOT EXISTS idx_bookmarks_folder  ON bookmarks(browser_folder);
CREATE INDEX IF NOT EXISTS idx_bookmarks_category ON bookmarks(category);
```

向量库：LanceDB 独立表 `bookmark_vectors`（`{dir}/.mdgo/lancedb/`，与文档 `vectors`
同目录不同表，避免被文档检索的扩展名过滤误伤）；列 = `id / bookmark_id / text /
vector`，写入为**增量 upsert**（按 bookmark_id 删除旧行再追加），检索为 cosine top-k。

## 命令面（Tauri）

- 现存（`lib.rs` invoke_handler 注册）：`bookmark_import` / `bookmark_list` /
  `bookmark_search` / `bookmark_stat` / `bookmark_get` / `bookmark_tree` /
  `bookmark_worker_start`（「分析扫描」触发 Worker）。
- 已删除：`bookmark_update`、`bookmark_archive`（UI 无调用点，非核心业务，
  全仓无残留）。

## 检索语义

- LIKE 关键词为主：`title / summary / category / tags` 模糊匹配，可选
  `category`（等值）与 `folder`（前缀）过滤；`failed/dead` 书签仍可检索
  （结果带状态，由调用方判断）。
- 向量补位：LIKE 命中不足 limit 时，对 ready 书签做向量召回补位（去重后按 id
  取详情）；embedding 失败静默降级 LIKE-only。
- 工具面：Agent 只经 `search_bookmarks` / `get_bookmark` 只读访问
  （`core/agent/tools`）；导入是 UI 行为，不暴露给 Agent。

## 边界

- Agent 只读访问书签（见上）；导入由 UI 完成。
- 浏览器模式（index.html / index_cdn.html）为独立 JSON 预览实现，与 Tauri 模式
  完全分离（无 Tauri 命令可用）。
