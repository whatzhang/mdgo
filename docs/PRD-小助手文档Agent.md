# PRD：mdgo「小助手」文档 Agent（右侧停靠栏问答 · DocAgent 组件化）

> **状态**：草案 v0.1（待评审）　**最后更新**：2026-09
> **目标版本**：mdgo v1.1
> **产品负责人 / 评审人**：（待填）
> **关联文档**：`docs/目录索引.md`（本文档已登记为「产品与规划」分类）
>
> **一句话定义**：在 mdgo 本地 Markdown 知识库中，为「正在打开的文档」贴身服务的**文档子 Agent（DocAgent）**。
> 它停靠在**主页面右侧栏**（TOC 右侧、同图层），默认自动「关联当前文件」，同时被**主 Agent 页作为子代理工具调用**（`doc_agent` / 多文件并行版），实现"一套能力、两种宿主"。

## 1. 背景与目标

### 1.1 背景

- 本地知识库用户的最高频场景是"**边读边问 / 边写边改**"。
- 现状：FAB「小助手」仅做单次请求；主 Agent 页以**整库 RAG** 为中心、面向**重任务**，缺少"跟随当前文档"的轻问答入口。
- 市场验证：Notion（✨ 页面级入口 + Q&A）、ima.copilot（浮窗感知）、Obsidian Copilot（可调宽边栏 + 自动注入当前笔记）、Craft（Explore/Execute）等已证明"打开对象 → AI 问答 → 可溯源/可写回"是标配能力。
- 竞品普遍短板：引用只到"文件级"、无法真正把结果落回正文、会话不沉淀为可检索资产——这正是本产品的机会点。

### 1.2 目标

1. 让**当前打开的文件（或选区）**成为一等问答单元，提供秒级、低成本、可溯源、可写回的文档问答体验。
2. 将问答能力**组件化为 DocAgent**，停靠栏与主 Agent 页共用同一内核与上下文工程，主 Agent 可将其作为子代理对多文件并行精读。
3. 复用并盘活既有资产：自研 `core/loop` 内核、五层混合检索、Skills/Prompt/MCP、审批门、事件溯源会话、AI 用量统计。

### 1.3 非目标（v1.1）

- 不做 Dify/RAGFlow 式通用检索平台（复用现有检索管线，不重复造轮子）。
- 停靠栏不承载 Planner、子代理调研、批量跨文件写、技能/MCP 管理（保留给主 Agent 页）。
- 不做云同步/多端（本地优先为卖点，远期另立项目）。
- 不做无授权目录外的任何文件访问。

## 2. 术语

| 术语 | 定义 |
|---|---|
| 小助手停靠栏（小助手） | FAB 头像切换的**右侧停靠栏**（停靠主页面右侧、TOC 右侧同图层，宽 400px），DocAgent 的宿主 A |
| DocAgent（文档子 Agent） | 以"单文件/选区"为上下文的可复用 Agent 组件，两种宿主的共同内核 |
| 宿主 A / B | A=停靠栏前台直连（用户在场、SSE 流式）；B=主 Agent 页通过工具 `spawn` 调用（后台隔离） |
| 关联当前文件 | 把当前文件（或其选区）纳入上下文的开关，停靠栏默认开 |
| 上下文档位 | 选区 / 当前文件 / 全知识库（三选一，选区优先） |
| 引用锚点 | 引用条目最小定位单元：`文件 + 标题 + 段落/行区间 + 修改时间`，可双向定位到编辑器 |
| 升舱 | 停靠栏会话转交主 Agent 页继续（或反向"聚焦到文件"降级） |
| Explore / Execute | 文档写回的二段式：Explore=先给方案/diff 待确认；Execute=直接改（每次仍过审批门） |

## 3. 用户与场景

### 3.1 目标用户

- 知识工作者 / 开发者 / 学生；使用 mdgo 管理个人 Markdown 库；倾向本地优先、隐私敏感；已是 Agent/RAG 的高级用户（v1.1 先服务存量高级用户，再向普通用户扩散）。

### 3.2 主要场景

| # | 场景 | 期望 |
|---|---|---|
| S1 | 读长文（30KB+ 文档） | 问"这篇讲了什么 / 第 3 节逻辑是什么"，答案带引用，点击跳到原文 |
| S2 | 改文 | 选区"改口语化 / 精简 / 翻译 / 润色"→ diff 预览 → 替换落盘 |
| S3 | 衍生创作 | "按本文出一份 5 条要点的周报 / 生成一张流程图"→ 新笔记落盘并回链 / 打开对应视图 |
| S4 | 跨库提问 | "所有文档中关于 X 的讨论"→ 自动切全库混合检索，跨文件引用 |
| S5 | 主 Agent 深读 | "逐个精读这 10 篇文件并汇总差异"→ 主 Agent 并行派发多个 DocAgent |
| S6 | 写作者防打断 | 在写作中随时唤起而不离开编辑器（停靠栏不抢主编辑焦点区） |

## 4. 与现有 Agent 页的分工与护栏

### 4.1 一句话分工

- **主 Agent 页 = 知识库工作台**：以**整库**为上下文，面向**重/长任务**（规划、深度调研、跨文件改造、技能/MCP/写文件全开）。
- **小助手停靠栏 = 文档陪读/伴写**：以**当前文件（或选区）**为上下文，面向**轻/即时任务**（读懂、总结、改写、续写、结构化生成并落回正文）。

### 4.2 差异对照表

| 维度 | 主 Agent 页 | 小助手停靠栏 |
|---|---|---|
| 入口心智 | dashboard→"Agent"，主动发起任务 | 编辑器 FAB 头像，跟随"我正在读/写什么" |
| 默认上下文 | 整库（当前目录 RAG） | 当前文件 + 选区（可升为全库） |
| 任务深度 | Planner / 子代理 / parallel / 记忆 / 30+ 工具 / 写文件 | 单轮~短链问答/改写/结构化；不重规划 |
| 工具面 | 全量注册表 | **只读子集 + 当前文件写回**（写前 diff 确认） |
| UI 密度 | 会话历史列、RAG 参数、Skill chips、trace、全局任务条 | 文件卡片 + 快捷动作 + 消息 + 引用条目 |
| 输出去向 | 结论留对话 / 落新笔记 | **插入光标 / 替换选区 / 复制 / 存新笔记** |
| 引用粒度 | 来源列表（文件级） | **段落/行级双向定位** |
| 会话模型 | 长期会话、fork、收藏 | 按文件聚类短会话，随文件切换提示"继续/新开" |
| 模型/成本 | 深度档为主，用户管理 | 默认快速档，深度档可选，token/用量可见 |
| 写权限 | 完整 ApprovalGate | 默认只读；写回 = Explore/Execute 二段式确认 |

### 4.3 三条护栏（防左右互搏）

1. **同引擎、同资产、不同开关**：共用 `core/loop`、检索管线、会话存储、Prompt/Skill 库；禁止另起一套问答实现。
2. **升舱不重做**：停靠栏会话一键"转主 Agent 继续"，上下文无缝交接；主 Agent 侧会话可"聚焦到某文件"降级为停靠栏视角。
3. **能力边界显性化**：停靠栏遇到"需要规划/跨文件改造/整库任务"意图时**主动提示升舱**，不硬做；主 Agent 页不做选区级插入/替换这类编辑器微操作（归停靠栏），避免编辑落盘逻辑两处重复。

## 5. DocAgent 组件化架构（一能力，两宿主）

### 5.1 调用关系

```
                          DocAgent（可复用 · 单文件/选区）
        上下文构建(直读≤阈值 / TOC分层 / 单文件检索) · 引用锚点 · 结果契约
                              ▲                          ▲
          宿主 A：前台直连(SSE流式)            宿主 B：spawn 子代理(后台隔离)
                              │                          │
                     ┌────────┴────────┐        ┌────────┴─────────┐
                     │ 小助手停靠栏(右侧) │        │ 主 Agent 页        │
                     │  用户在场/可停止     │        │ doc_agent 工具调用   │
                     │  会话按文件聚类      │        │ 并行派发多文件(仿parallel_research)
                     └───────────────────┘        └──────────────────┘
```

### 5.2 DocAgent 规格

**入参（结构化契约）**

```jsonc
{
  "filePath": "相对/绝对路径",
  "selection": { "start": 0, "end": 0, "text": "" },   // 可选
  "question": "…",
  "mode": "ask | summarize | rewrite | outline | structure | translate | …",
  "writeAllowed": false,          // true 时挂载"仅限该文件"的写工具
  "maxTurns": 12,                 // 默认 12，上限 30
  "scope": "file"                 // 预留：升级整库走主链路
}
```

**上下文构建规则**

| 文件规模 | 策略 |
|---|---|
| ≤ 阈值 token（默认按模型窗口预算） | 直读全文注入（含标题/路径/修改时间元数据） |
| > 阈值 | 按标题 TOC 分层，只带相关章节；必要时对该文件做**单文件检索** |
| 有选区 | 默认选区优先，可回落到整篇 |

**工具白名单**

- 只读：`read`（限目标文件 + 显式邻居）、`doc_search`（仅限该文件检索）、`grep/ls`（只读）。
- 写（`writeAllowed=true` 且审批通过时挂载）：`edit_file`（**仅限目标文件**，diff → 审批上抛父链/停靠栏弹窗）。
- 禁止：spawn 子代理（防递归）、跨文件写、Skill 激活注入面工具、deep_research（防递归）。

**输出契约**（与现有 `deep_research` 的"有界摘要 + subagent_id + LRU 全量"模式对齐）

```jsonc
{
  "summary": "有界结论（回传父链/直接渲染）",
  "full_result_id": "LRU 可读 id",          // 宿主 B 场景走 read_subagent_result
  "citations": [{ "file": "…", "title": "…", "section": "…", "lineStart": 1, "lineEnd": 20, "quote": "…", "mtime": "…" }],
  "confidence": "high|medium|low",
  "need_human_check": false
}
```

**运行语义**

- 取消：沿用父链 CancellationToken 透传；停靠栏"停止"即时生效，已生成部分保留。
- 会话：宿主 A 落独立 doc 会话（事件溯源，按文件聚类）；宿主 B 以工具结果形态回传，**不落主会话**（不污染上下文）。
- 模型路由：宿主 A 默认快速档、深度档可选；宿主 B 由主 Agent 上下文决定（可深度档）。
- 防递归与隔离：白名单注册表层过滤 + 独立 request_id（`doc-{uuid}`）+ LruResultStore 有界。

### 5.3 宿主矩阵

| 行为 | 宿主 A（停靠栏） | 宿主 B（主 Agent 页） |
|---|---|---|
| 启动 | 用户点头像 | 主 Agent 调用 `doc_agent` 工具 / 并行版 `parallel_doc_agent` |
| 运行 | 前台 LoopAgent 直连，SSE 流式 | SubagentRunner 后台隔离 |
| 停止 | 面板"停止"按钮 | 主 Agent 页任务取消（含全局任务条） |
| 展示 | 消息 + 引用 + 写回按钮 | 工具轨迹卡片：`doc_agent(file)→有界结论`，全量可点开 |
| 写回 | Explore/Execute 二段式 | 仅当父链挂审批门且批准 |
| 会话落库 | doc 会话 | 不入主会话 |
| 升舱 | "转主 Agent 继续" | 选中文件 → "在此文件上开停靠栏会话" |

## 6. 交互与信息架构（停靠栏宿主）

### 6.1 打开与默认状态

```
打开文件 → 点击 #ai-fab-button
  → 停靠栏在主页面右侧出现（TOC 右侧同图层，宽 400px；再点头像/Esc/Alt+Q 隐藏）
  → 「关联当前文件」默认打开（#ai-link-file=on）
  → 顶栏文件卡片显示：文件名/路径/修改时间/行数/索引状态
  → 有选区时提示："已选择 N 字（自动带入）"；提供"忽略选区，用整篇"
  → 无已打开文件时：开关置灰，提示"打开文件后即可关联"，并可用全库问答
```

### 6.2 面板结构

```
┌ 小助手（停靠右侧栏） ───────────────────────────────┐
│ [文件卡片: xx.md · 已关联]  [范围: 本文件]             │
│ 快捷动作: 总结 | 分析 | 排版 | 提问 | 润色 | 翻译 | 生成脑图…(可配置) │
│ ── 消息区 ────────────────────────────────  │
│  思考过程/工具轨迹(折叠) · 回答(流式) · 引用条目(hover/点击定位)  │
│  消息操作: 复制 | 重新生成 | (写回: 插入光标/替换选区/diff预览)  │
│ ── 输入区 ────────────────────────────────  │
│  [多行输入…]  [发送/停止]  @文件/@标签  token 用量  [升舱: 转主Agent] │
└─────────────────────────────────────────────┘
```

### 6.3 会话与历史

- 会话自动保存；AI 自动起标题；历史按**所属文件**聚类展示（"xx.md 的对话记录"）。
- 文件切换：提示"继续上次关于本文的会话 / 新开会话"。
- 停靠栏会话可一键升舱：转交主 Agent 页继续（上下文含文件、选区、历史）。

## 7. 功能需求

### 7.1 P0（首版可用）

| # | 需求 | 验收标准 |
|---|---|---|
| P0-1 | FAB → 右侧停靠栏（宽 400px，停靠主页面右侧、TOC 右侧同图层） | 停靠栏显示于 TOC 右侧；再点头像/Esc 隐藏；文件视图宽度随停靠栏开合自适应 |
| P0-2 | 打开文件后自动开「关联当前文件」，顶栏文件卡片实时更新 | 默认 on；文件切换即更新；显示文件路径/修改时间/行数 |
| P0-3 | 三档上下文（选区/本文件/知识库），选区优先、可回落 | 有选区显示"N 字已带入"；切档即时生效 |
| P0-4 | 本文件问答：≤阈值直读全文；>阈值 TOC 分层/单文件检索 | 大文件首答 P50 ≤ 8s；答案忠于原文 |
| P0-5 | 快捷动作（Prompt/Skill 库驱动，可配置显示项） | 与主链路共用 Prompt 定义；动作后流式出结果 |
| P0-6 | 流式回答 + 停止 + 重新生成；思考/tool 折叠时间线 | 与主 Agent 页体验一致（复用 core/loop） |
| P0-7 | 引用溯源：段落/行锚点、hover 预览、点击跳转编辑器定位 | 引用可点击且定位准确；"未找到/不确定"有明确文案与 low 置信标注 |
| P0-8 | 写回三件套：插入光标 / 替换选区 / 复制（本文件会话内） | 写入落盘正确、可撤销；替换走 diff 预览确认 |
| P0-9 | 会话保存 + 历史（按文件聚类、AI 起标题、可继续） | 重启后能恢复并继续；切换文件提示新开/继续 |
| P0-10 | 模型：沿用现有 profile；快速/深度两档；token 与用量可见 | 轻问答默认走快速档；用量随消息展示 |
| P0-11 | DocAgent 内核：单文件上下文构建 + 只读白名单 + 输出契约 | 与主 Agent 页同一 LoopAgent 跑通；引用契约含锚点字段 |
| P0-12 | 主 Agent 页工具调用：`doc_agent(file, question)` 工具 | 主 Agent 可对指定文件触发 DocAgent；结果以工具卡片+有界摘要呈现 |

## 8. 功能开关对照表（停靠栏 vs 主 Agent 页）

| 控件/能力 | 主 Agent 页 | 小助手停靠栏 |
|---|---|---|
| Planner 计划卡片 + 审批 | ✅ | ❌（遇复杂意图提示升舱） |
| 子代理 deep_research / parallel_research | ✅ | ❌ |
| doc_agent / parallel_doc_agent 工具 | ✅（调用方） | —（DocAgent 本体） |
| Skill 激活与技能 chips | ✅ | 🔲（仅动作条，来自 Prompt/Skill 库） |
| MCP 服务器/工具管理 | ✅ | ❌ |
| RAG 参数调节面板 | ✅ | ❌（沿用主链路默认值） |
| trace 阶段面板 | ✅ | 🔲（折叠时间线子集） |

## 9. 安全与隐私边界

1. **文件边界**：DocAgent 只访问当前知识库根（`.mdgo/` 授权目录）内文件；引用不越过授权目录。
2. **只读默认**：停靠栏默认只读；任何落盘 = Explore(diff) → 确认 或 Execute + ApprovalGate。
3. **提示注入**：文档内容视为不可信输入；沿用证据校验（verify_grounding）与注入包裹；不改动非目标文件。
4. **数据外发透明**：每个请求展示"发送了哪些文件片段 → 哪个模型 → 多少 token"；本地 embedding 默认开启；提供"仅本地模型"模式。
5. **防递归/隔离**：DocAgent 白名单不含 spawn/deep_research；独立 request_id；LRU 有界。
