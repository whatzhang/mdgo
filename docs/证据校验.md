# 证据校验（Evidence / Grounding Check）

最后更新：2026-08-23

> 轻量规则版证据校验（C2，默认关）：从回答中提取"证据型断言"，检查检索上下文中是否有足够证据。
> 实现位于 `tauri/src-tauri/src/core/evidence.rs`，接入点位于
> `tauri/src-tauri/src/commands/llm.rs`（`agent_generate_loop_v2` 末尾）。
> 零 LLM 成本、确定性、可测试——适合本地单机。

---

## 1. 定位

- **普通查询默认不开启**（`evidence_check_enabled` 默认 `false`），不增加任何延迟；
- 开启时在回答尾部标注"未获检索上下文支撑"的断言，供用户判断可信度；
- **LLM 深度校验（Claim Extraction → Verify）留作后续增强**——本实现只做词法规则判定。

---

## 2. 接口

```rust
pub fn verify_grounding(
    answer: &str,       // 模型生成的回答全文
    context: &str,      // 本次请求送入模型的检索上下文文本
    min_hit_ratio: f64, // 证据判定：关键 token 命中比例下限
    min_hits: usize,    // 证据判定：关键 token 绝对命中数下限
    max_claims: usize,  // 返回无证据断言的上限（防刷屏）
) -> Vec<String>
```

调用点参数（`commands/llm.rs:2281-2287`）：

```rust
let claims = crate::core::evidence::verify_grounding(&full_content, &context, 0.5, 1, 3);
```

即 `min_hit_ratio = 0.5`、`min_hits = 1`、`max_claims = 3`。

---

## 3. 判定流程

```text
回答全文
  │
  ▼ ① 按句子边界切分（。！？\n；英文 . ! ?）
  ▼ ② 长度过滤 [8, 200] 字符（过短/过长跳过）
  ▼ ③ 仅"证据型"断言：含数字，或 ≥2 个 ≥3 字符的拉丁词（专名/术语/代码符号）
  ▼ ④ 提取关键 token：≥4 字符的词/数字（含下划线，覆盖代码符号），统一小写
  ▼ ⑤ 子串命中：token 是否出现在检索上下文（小写化）中
  ▼ ⑥ 判定无证据：hits < min_hits 且 hits/总数 < min_hit_ratio
  ▼ ⑦ 收集无证据断言，最多 max_claims 条
```

规则逐条说明：

1. **句子边界**：`。！？\n` 与英文 `. ! ?`（`evidence.rs::split_claim_sentences`）；
2. **长度过滤**：`s.len() < 8 || s.len() > 200` 跳过（注意是**字节长度**，见 §6 已知限制）；
3. **证据型判定**（`has_digit || latin_words >= 2`）：
   - `has_digit`：含 ASCII 数字；
   - `latin_words`：按非字母数字切分后，长度 ≥3 的词的数量 ≥2；
   - 纯口语/模糊句（如"你好""这很重要"）被跳过，不做判定；
4. **关键 token**：按 `is_alphanumeric || '_'` 切分，取长度 ≥4 的 token 小写化；
5. **证据命中**：token 作为**子串**在 `context.to_lowercase()` 中匹配；
6. **无证据判定**：`hits < min_hits && (hits / tokens.len()) < min_hit_ratio` 两条同时满足。

---

## 4. 接入点与输出

- 位置：`commands/llm.rs` `agent_generate_loop_v2` 的 `Done` 分支末尾（`rag:done` 事件发出前）；
- 开关：`IndexerConfig.evidence_check_enabled`（`core/config.rs:35-37`，**默认 `false`**）；
- 行为：开启且存在无证据断言时，在回答尾部追加标注并记 warn 日志：

```text
⚠️ 以下论断未在检索内容中找到充分证据（可进一步核实）: <断言1>；<断言2>；<断言3>
```

（格式见 `commands/llm.rs:2297-2300`；断言以 `；` 连接，日志 tag `[agent_query_v3] 证据校验`。）

示例：

```text
该系统的延迟是 42 毫秒。

⚠️ 以下论断未在检索内容中找到充分证据（可进一步核实）: 该系统的延迟是 42 毫秒。
```

## 5. 后续增强（未实现）

- **LLM 深度校验**：Claim Extraction（抽取声明）→ Verify（逐条判定），语义级判定；
- **CJK 感知 token 化**：bigram / 去停用词，替代当前字节长度切分（见 §6）。

## 6. 已知限制

以下问题如实记录（引用《代码审查报告-RAG全链路P0批次.md》）。**2026-08-23 已修复：**
M15（CJK 2-gram 词法判定）、L21（句点数字保护）、M23（开关已接线命令参数与前端设置项）：

| # | 状态 | 问题 | 影响 |
|---|---|---|---|
| M15 | ✅ 已修复 | 旧实现用**字节长度** `w.len() >= 4` 切 token，中文句子整体成一个长 token 与上下文做子串匹配 | 中文改写断言（同义表述）0 命中即误标"无证据"；现按 CJK 2-gram 切分，改写表述可命中 |
| L21 | ✅ 已修复 | 句子切分对 `.` 无上下文保护：`3.14`、`v2.0`、`Redis 6.2.0` 被切散 | 现仅当句点后随空白/结尾才切分，数字/版本/URL 不再被拆散 |
| M23 | ✅ 已修复 | `evidence_check_enabled` 无命令参数与前端入口（死配置） | 现 `kb_update_indexer_config` 接受 `evidence_check_enabled`，main.html RAG 设置面板新增"证据校验"开关 |

**剩余限制**：`min_hits=1` 时 `min_hit_ratio` 条件恒真（判定退化为"0 命中即标记"，
属当前调用参数下的设计语义，非缺陷）；LLM 深度校验（语义级 claim verify）未实现。

结论：当前实现为**规则级实验特性**（默认关），已可经 UI 开启；对中文回答的误报
已大幅缓解，但复杂改写仍可能漏检/误检——启用前建议先跑 `retrieval_eval` 验证。
