## 0. 当前检索链路真实状态（与用户假设的差异）

用户假设："单一 Hybrid Search = BM25 + Vector + 加权融合，直接给 LLM"。**实际已经是一条多阶段管线**：

```text
Query
 → RuleQueryPlanner（intent 路由 + 符号提取 + 标签提取）    [已有] query_plan.rs
 → Filter 前置（intent 扩展名白名单 + tag 过滤 SQL 下推）   [已有] hybrid_recall
 → 多路召回：Dense ∥ BM25 ∥ Symbol（第三路）               [已有] hybrid_recall
 → RRF 融合（alpha 动态权重：intent 偏置 + 查询长度）       [已有] compute_alpha + rrf_fuse
 → 双阈值（vec_min_score / rerank sigmoid）                [已有]
 → 精排（LocalBgeReranker cross-encoder，失败降级 RRF）     [已有] rerank.rs + B5 分数缓存
 → 聚簇（文件级 max_chunks_per_doc + OPML 层级去重 + 轻量 MMR + 概览降权） [已有] finalize_hits
 → ±window 上下文扩展（fetch_chunks_between 邻接召回，上限 6000 字符） [已有] finalize_hits
 → 预检索优化器（多查询：原始+LLM扩展+符号实体变体+embedding 去重）     [已有] commands/llm.rs
 → 池级去重 + 按来源查询精排取 max + 跨查询一致性加成       [已有] rerank_pool + agreement_bonus
 → 上下文组装（doc 分组、阅读序、sentence_window、预算）    [已有] agent/mod.rs build_context_text
```

即：用户方案 §五/§六/§七/§八/§十三/§十五 的主体**早已存在**；评估时的差距（Metadata、FrontMatter、MMR、缓存、证据校验、Benchmark、标签过滤）在 **V1/V2/V3 + RAG P0 批次**中已逐一落地（见 §6/§7 与 §1 落地状态列）。

## 4. 响应速度专项（用户重点要求）——现状复核

当前延迟构成（本地）：向量检索（IVF-SQ）→ BM25（tantivy）→ **rerank（cross-encoder 最贵）** → 上下文组装。

| 手段 | 效果 | 说明 | 现状 |
|---|---|---|---|
| **adaptive candidate_k** | 池缩小 → rerank 推理量下降 | General 60 / Code 40 / Document 80（min(candidate_k)、max(top_k)） | ✅ 已落地（B2） |
| **RRF 后精排截断** | rerank 只处理 RRF Top-50 | `RERANK_MAX_CANDIDATES=50`（单查询路径） | ✅ 已落地（B2b）；`rerank_pool` 未套用（审查 M16） |
| **查询 embedding 缓存** | 高频重复查询零推理 | 进程内 LRU，容量 512，键 = 查询文本 FNV-1a | ✅ 已落地（B1）；键不含 model/dim（审查 M19） |
| **IVF-PQ 参数调优** | 向量扫描加速 | nlist/nprobe 按库规模自适应（现有 `ensure_vector_index` 固定参数） | ⏳ 未做（当前库规模下非瓶颈） |
| **元数据过滤下推** | 向量/BM25 扫描范围缩小 | tags 过滤下推 + 扩展名白名单 | ✅ 已落地（A3 + FLOW-1） |
| **并行** | 已有（tokio::join / join_all / rayon / buffer_unordered） | 保持 | ✅ 保持 |

**量化现状**（本地 CPU，`retrieval_eval` 42 条基准实测）：rerank 不截断首跑 avg **5644ms**；精排截断 50 后基线 v2 avg **1290ms**（−77%）；重复查询缓存命中路径预期显著更低（<100ms 目标仍未单独实测）。目标口径不变：单查询全链路（含 rerank）< 500ms 为长线目标。

## 5. 最终结论（现状复核）

1. **用户方案的架构判断正确，且与项目现状高度契合**——项目早就是多阶段管线（intent 路由 → 三路召回 → RRF → reranker → 聚簇 → 上下文扩展 → 多查询精排），**不是"单一 Hybrid Search"**。评估时的 5 项差距（Metadata、FrontMatter、标题独立表示、Parent-Child 整节召回、Retrieval Benchmark）中，4 项已落地或部分落地（见 §1 落地状态列）。
2. **不做**的事（本地单机约束）保持不做：多份独立 embedding（×3 成本）、通用 Entity Graph（构建成本高）、每轮 LLM Evidence 校验（延迟 ×2）。
3. **立即做**（P0，低成本高收益）：FrontMatter 元数据、Metadata 路 + 过滤下推、Retrieval Benchmark —— **全部已完成**（P0-1/A3/P0-3）。
4. **随后做**（P1）：标题独立 chunk、MMR、QueryPlan 增强 + adaptive candidate_k、查询 embedding 缓存 —— **已完成**；Parent-Child 整节召回 —— **未做（剩余工作 §8-1）**。
5. **度量先行**：`retrieval_eval` 42 条正式基准集 + 基线记录已建立（见 §7 A1）——后续任何改动（chunk/embedding/rerank/query planner）都以它验收。

> 一句话（复核）：**方向全部认可，评估时的落地顺序建议已执行完毕——检索管线已补齐元数据、立起度量，并进一步落地了 RAG P0 批次（token 预算分块 / 缓存 / 标签过滤 / 证据校验）；剩余工作收敛为 4 个可选增强（见 §8）。**
